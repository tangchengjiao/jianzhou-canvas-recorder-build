# 见舟画布录制 · 发布与上传清单

## 文件放在哪里

| 文件 | 位置 | 用途 |
| --- | --- | --- |
| README、使用手册、界面截图、联系二维码 | 源码仓库 | 用户打开仓库即可看到介绍、教程和联系方式 |
| `src/`、`src-tauri/`、`scripts/`、`public/`、工程配置与锁文件 | 源码仓库 | 开发和复现构建；现有文件已在仓库内 |
| Windows 的 `Windows-x64-setup.exe` | GitHub Releases → 对应版本 → Assets | 用户安装 |
| Mac 的 `macOS-Universal.dmg` | GitHub Releases → 对应版本 → Assets | Apple Silicon / Intel 用户安装 |
| PDF 手册、内测说明、隐私说明、第三方说明 | GitHub Releases → 对应版本 → Assets | 随安装包提供使用说明 |
| `node_modules/`、`dist/`、`src-tauri/target/` | 留在本机 | 依赖与构建中间产物，不重复提交 |
| 本机录制视频、导入资料、项目状态、原始诊断日志 | 留在本机 | 个人使用数据 |

安装目录中的 `jianzhou-canvas-recorder.exe` 是已经安装后的主程序，`uninstall.exe` 是卸载器。向新用户分发时使用构建好的 `setup.exe`，无需把整个安装目录上传；也无需从 EXE 反向恢复源码。

GitHub 的 **Code → Download ZIP** 下载源码。安装文件应在 **Releases → Assets** 中提供，README 顶部同时给出直达链接。

## 发布后用户如何找到

1. 仓库 README 顶部：直接点击 Windows / Mac 下载链接。
2. 仓库右侧 Releases：进入版本并展开 Assets。
3. 收藏固定入口：<https://github.com/tangchengjiao/jianzhou-canvas-recorder-build/releases>。

不要将 Actions 临时构建工件当成长期下载入口。macOS 构建成功后由工作流将 DMG 同步到对应版本的 Releases；首次发布新版本时，再补充匹配的 Windows 安装包和说明。

## 后续发新版本

1. 更新 Tauri 产品版本，按平台完成构建和试录。
2. 使用 `v版本号` 建立 Beta Release。Mac 工作流会上传同版本 DMG；Windows 安装包放到同一个 Release。
3. 附上本版使用说明，填写实际变更与已知限制。
4. 更新 README 的当前版本、文件名和两处平台下载入口；未发布的平台保留真实旧版号。
5. 检查 Releases 页面和下载链接可访问后，再对外分享。
